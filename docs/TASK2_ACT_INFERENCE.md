# 任务2 ACT 真机推理

三个策略分别位于：

- `models/task2_act/button`
- `models/task2_act/knob`
- `models/task2_act/switch`

模型动作只用于 G1 右臂 7 个关节和右 Dex1-1。由于 Arm SDK 的公共权重覆盖腰部和双臂，部署器还会在接管前记录腰部、左臂实测姿态，并显式保持这些关节；不能把它们的零增益字段当作“不接管”。腰部默认使用 `kp=40`、`kd=2.0`，左臂使用 `kp=28`、`kd=1.8`，随 Arm SDK 权重从零平滑生效；仍低于 Unitree 官方 7DOF Arm SDK 示例对腰部和双臂使用的 `kp=60`。腿部不发布关节目标，仍由原厂平衡控制负责。机器人应处于常规运控稳定站立状态；不要同时启动 SONIC、任务1行走或 PICO 手臂遥操。

真机启动必须收到新鲜的底盘里程计（`rt/odommodestate` 或 `rt/lf/odommodestate`）和 IMU。初始倾角超过 `0.12 rad` 或平移速度超过 `0.03 m/s` 时拒绝接管。执行中监测三个腰关节、左臂偏移、躯干倾角以及底盘位移/速度；任一腰关节偏移超过 `0.10 rad`、左臂偏移超过 `0.20 rad`、倾角变化超过 `0.08 rad`、绝对倾角超过 `0.20 rad`、航向变化超过 `0.10 rad`、平移超过 `0.04 m` 或速度超过 `0.12 m/s` 时，打印 `[BODY STOP]` 并请求立即释放 Arm SDK、失败退出。里程计过期也会释放。`[BODY]` 日志分别记录 `waist_yaw/roll/pitch`，便于判断具体漂移关节。

这些是保守的初次调试门限，不能保证原厂平衡控制绝不迈步，也不是物理锁定。腰部和左臂保持增益、运动门限尚需真机验证。发生身体异常时仍应使用原厂急停；不要通过锁死腿部或关闭平衡控制绕过检查。

## 防抖策略

模型以 20 Hz 产生 100 步动作块，后台异步重规划；机器人命令环以 50 Hz 运行。部署程序对重叠动作块做时间对齐和集成，然后依次执行线性插值、1.5 Hz 低通、速度限制、加速度限制、示教范围限制和跟随误差限制。推理、相机或机器人状态超时后会平滑释放 Arm SDK。

温度默认只报警，不再在 70℃时由本程序释放 Arm SDK；机器人自身的温度报警和保护仍然有效。如需恢复软件侧 70℃释放，可追加 `--thermal-action release`。

真机不再从常规运控直接跳到模型动作。启动后先用低增益 `kp=16`、`kd=1.5` 在约 2.1 秒内把 Arm SDK 权重缓升到 0.25，同时逐帧跟随实测姿态，不请求关节位移。随后进入 `ARMING`：固定当时右臂和 Dex1 的完整 8 维目标，在约 6.5 秒内将权重升至 0.90，增益在 5 秒内升至 `kp=28`、`kd=1.8`，不提前移动到示教姿态。权重、增益到位且实测关节速度不超过 `0.12 rad/s` 连续 1 秒后，才进入 `PREPOSITION`，以最多 `0.12 rad/s` 靠近示教中位起始姿态。预定位过程中权重和增益保持不变；`ARMING` 到 `PREPOSITION` 沿用上一条目标，不重置为实测角度。默认 `ARMING` 持续约 7.5 秒，属于正常等待；`--max-run-seconds 3` 仍仅限制后面的 ACT 策略时间，不包含准备阶段。

这次拆分针对日志中“预定位目标移动与控制权重、增益同时增长”的耦合：腕部先跟随滞后，随后出现实测超速。它不证明已排除静摩擦、负载或与常规运控的相互影响，必须再看真机结果。`ARMING` 仍检查 `0.16 rad` 保持误差、实测速度、源过期和 20 秒阶段超时，不通过提高速度门限掩盖异常。

是否完成预定位不再要求每个关节精确贴合单一中位数。程序按各模型训练集第一帧的 `observation.state` 统计右臂 7 关节和 Dex1 的第 10～90 百分位范围；实测状态进入该训练起点分布（默认允许额外 `0.05 rad`，约 2.9° 的实机阻抗跟踪裕量）并稳定 1 秒后，才开始第一次 ACT 推理。该裕量仍受 `0.16 rad` 预定位命令跟随误差硬限制约束。这能避免为了追逐单一角度而持续加力，同时保证策略从训练数据附近启动。策略阶段继续使用 `kp=28`、`kd=1.8`。

接管、慢速对齐或策略执行期间，若测得异常关节速度、跟随误差、状态/相机超时，程序会释放 Arm SDK 并以非零状态退出。温度仍为只报警模式，机器人本体保护不受影响。

预定位切入 ACT 时，策略滤波器继承上一帧发送的关节目标和速度，增益从预定位增益连续衔接到策略增益。不能在该切换点把目标重置为实测角度、把增益降回接管初值，否则会瞬间丢失维持右臂姿态所需的位置误差和支撑力。正常释放末帧显式发送 Arm SDK 权重 0。

关节速度保护使用同一帧 `rt/lowstate` 的电机反馈 `dq`，不使用“关节角差 / 电脑循环间隔”。DDS 更新、相机轮询和控制循环不同步，后一种算法可能放大速度。位置、速度及接收时间通过同一快照读取；重复帧保留反馈速度，不当作静止。预定位/接管的速度上限仍是 `0.60 rad/s`，策略阶段仍是 `1.50 rad/s`。超限日志会显示触发关节、实测 `dq`、按接收时间计算的位置差分（仅诊断）、帧间隔和样本年龄。速度反馈非有限或运行异常时，先尝试发送零接管权重，再关闭推理和相机。

当前控制修正版启动时打印 `[ACT][CONTROL] stationary-dq-v3`。控制循环在相机读取、策略取观测及退出渐退期间均检查中断；反馈缺失会直接释放并退出，不等待缺失反馈来完成渐退。`tests/test_task2_act_control_loop.py` 用假模型、假状态和虚拟时钟覆盖完整自动执行及退出流程，还覆盖初态偏离示教、低权重不跟随、保持误差下的连续交接及 ARMING 中断/超速/超时/源过期，不连接机器人。这些测试验证软件流程，不替代真实负载下的稳定性验证。

只读检查当前右臂各关节与某一模型示教起点的差异：

```bash
/home/drgh/g1_official/GR00T-WholeBodyControl/.venv_data_collection/bin/python \
  tools/check_task2_start_pose.py button
```

该工具只订阅 `rt/lowstate` 和 Dex1 状态，不创建任何命令发布器。

## 建议验证顺序

只检查本地权重和前向计算：

```bash
cd /home/drgh/shucai/g1_competition
bash run_task2_act_inference.sh button --offline-smoke
```

连接机器人和两路相机、运行完整策略但不发布任何控制命令：

```bash
bash run_task2_act_inference.sh button --dry-run
```

第一次真机验证只做“渐进接管 → 慢速进入训练起点分布 → 自动释放”，不会运行 ACT 动作：

```bash
bash run_task2_act_inference.sh button --real --preposition-only --exit-after-attempt
```

看到 `REAL ready` 后输入 `s` 回车。只有该过程平稳完成后，才运行单个按钮策略：

```bash
bash run_task2_act_inference.sh button --real --max-run-seconds 15
```

把 `button` 换成 `knob` 或 `switch` 即可选择另外两个模型。实时模式要求 CUDA 可用，并会校验三个模型的 SHA256。

完成单模型真机验证后，才可使用自动开始、不再输入 `s` 的命令：

```bash
bash run_task2_act_auto.sh button --real
```

同样可把 `button` 换成 `knob` 或 `switch`。这是直接控制真机的命令。

三个动作按“按钮 → 旋钮 → 拨杆”依次自动执行，中途无需人工切换模型。不要把它作为首次真机测试：

```bash
bash run_task2_act_sequence.sh --real
```

顺序模式不再按固定秒数认为动作成功。程序要求右臂完成与成功示教一致的“离开起始姿态 → 执行交互 → 返回起始姿态附近 → 稳定保持”完整周期，随后切换模型。每个动作默认最多 30 秒；若届时仍未检测到完整周期，会先释放 Arm SDK，再继续下一个动作。只有普通动作超时允许继续；相机、状态、身体、关节、推理或人工停止故障仍会终止整个序列。动作之间释放 Arm SDK 并等待 3 秒。

可用环境变量修改失败超时，例如：

```bash
TASK2_BUTTON_TIMEOUT_SECONDS=35 TASK2_KNOB_TIMEOUT_SECONDS=35 \
TASK2_SWITCH_TIMEOUT_SECONDS=35 TASK2_SEQUENCE_PAUSE_SECONDS=2 \
bash run_task2_act_sequence.sh --real
```

任一模型发生相机、机器人状态、推理或跟随错误时，序列会释放右臂并停止，不会继续执行下一模型。

该判据确认的是机器人完整执行了示教中的运动周期。现有数据没有按钮/旋钮/拨杆的成功标签，也没有力或触觉通道，因此它不能独立证明电柜机构已经物理生效；若比赛要求对物理结果做闭环确认，还需要为三个机构增加视觉状态检测或力/触觉判据。

程序就绪后，在同一终端输入：

- `s` 回车：开始一次最多 20 秒的自主执行
- `x` 回车：立即平滑释放本次执行
- `q` 回车：释放并退出
- `Ctrl+C`：软件紧急释放，立即发送 Arm SDK 权重 0 并退出，不等待渐退

`Ctrl+C` 不是硬件急停：它依赖电脑进程、网线和 DDS 通信正常。出现剧烈异常运动时应优先使用原厂遥控器急停，`Ctrl+C` 作为同时执行的软件停止手段。

开始前必须把机器人放在与示教数据相近的电柜相对位置。ACT 没有单独的任务完成分类头，因此每次执行达到时限后会自动释放；看到任务已经完成时可提前输入 `x`。

## 常用防抖参数

例如进一步降低策略速度（会增加动作时间）：

```bash
bash run_task2_act_inference.sh button --real \
  --cutoff-hz 1.2 \
  --arm-speed 0.25 \
  --arm-acceleration 0.7
```

不要让两个控制程序同时发布 `rt/arm_sdk`。启动器会拒绝与 `task2_right_arm_teleop.py` 同时运行，但现场仍需确认 SONIC 已停止。
